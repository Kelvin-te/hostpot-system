# WinguFi Core Integration Guide

## Architecture Overview

Company Laravel applications communicate with WinguFi Core via API to synchronize network authorization data. WinguFi Core then communicates with FreeRADIUS for actual network access control.

```
Company Laravel A ──┐
                    │
Company Laravel B ──┼──→ WinguFi Core → FreeRADIUS → MikroTik
                    │
Company Laravel C ──┘
```

## RADIUS Credentials and Captive-Portal Handoff

The company Laravel application is responsible for the final MikroTik hotspot login step. After a successful authorization, it:

1. Generates a per-authorization RADIUS username and a random 16-character password.
2. Encrypts the password locally using Laravel's `Crypt` facade and stores it in `hotspot_authorizations.radius_password_encrypted`.
3. Sends the plaintext password to WinguFi Core when syncing the client (`POST /api/v1/clients`). WinguFi Core must accept the optional `password` field, hash it with bcrypt, and store it in `network_clients.password_hash`. The plaintext password must never be returned in API responses or stored in plain text on the Core side.
4. Renders an auto-submitting HTML form that `POST`s the RADIUS credentials to the MikroTik router's `link_login` URL.
5. Signs the handoff URL so it expires after 5 minutes and validates the requesting client's IP address before revealing the credentials.

This design keeps the company app as an intermediary: it never writes directly to the FreeRADIUS database, and it never exposes credentials except during the final, time-limited handoff.

## Authentication

Each company Laravel instance authenticates with WinguFi Core using an opaque bearer token.

### Credential Provisioning

Create a credential from the WinguFi Core server:

```bash
php artisan wingufi:credential:create --tenant=<tenant_id>
```

This prints a plaintext bearer token once. Copy it immediately. Example:

```
wc_abc123:xxxxxxxx... (64 random characters)
```

The token is split into `client_id` (before the colon) and a secret (after the colon). Only a bcrypt hash of the secret is stored.

### Revocation

```bash
php artisan wingufi:credential:revoke <credential_id>
```

### Sending Requests

Every API request (except health) must include:

```http
Authorization: Bearer <client_id>:<secret>
```

Do not send the token over HTTP in production. Always use HTTPS.

## Environment Configuration (Laravel)

Add these values to the company Laravel application's `.env`:

```dotenv
WINGUFI_CORE_BASE_URL=https://wingufi-core.example.com/api/v1
WINGUFI_CORE_API_TOKEN=wc_clientId:secret
WINGUFI_CORE_ENABLED=true
WINGUFI_SOURCE_SYSTEM=admin
```

- `WINGUFI_CORE_BASE_URL` – WinguFi Core API base URL.
- `WINGUFI_CORE_API_TOKEN` – Bearer token issued by WinguFi Core.
- `WINGUFI_CORE_ENABLED` – Set to `false` to disable sync (useful for local dev).
- `WINGUFI_SOURCE_SYSTEM` – Unique identifier for this Laravel instance; included in every sync payload as `source_system`.

## Synchronization Pattern

### Idempotent Synchronization

Use `external_id`, `external_type`, and `source_system` to prevent duplicates:

```php
// Laravel payment creates authorization
$authorization = NetworkAuthorization::updateOrCreate(
    [
        'external_id' => $payment->id,
        'source_system' => 'company_a_laravel',
    ],
    [
        'tenant_id' => $tenant->id,
        'client_id' => $client->id,
        'package_id' => $package->id,
        'source_type' => 'payment',
        'username' => $user->phone,
        'status' => 'active',
        'starts_at' => now(),
        'expires_at' => now()->addSeconds($package->validity_seconds),
        // ... other fields
    ]
);
```

The matching `NetworkClient` record must be created/updated with the RADIUS password generated by Laravel so FreeRADIUS can authenticate the username.

### Package Synchronization

Synchronize network packages from Laravel billing system to WinguFi Core:

```php
NetworkPackage::updateOrCreate(
    [
        'external_id' => $localPackage->id,
        'source_system' => 'company_a_laravel',
    ],
    [
        'tenant_id' => $tenant->id,
        'name' => $localPackage->name,
        'code' => $localPackage->code,
        'download_speed' => $localPackage->bandwidth_download * 1000000, // Mbps to bps
        'upload_speed' => $localPackage->bandwidth_upload * 1000000,
        'validity_seconds' => $localPackage->validity_days * 86400,
        'data_limit_bytes' => $localPackage->rate_limit_bytes,
        // ... other fields
    ]
);
```

### Client/Authorization Creation

When a customer purchases a package:

1. Create or update network client, including the RADIUS password.
2. Create network authorization.
3. WinguFi Core makes the authorization (and its hashed password) available to FreeRADIUS.

```php
$radiusPassword = Str::random(16);

// Store encrypted locally (Laravel side)
$localAuthorization->update([
    'radius_username' => $user->phone,
    'radius_password_encrypted' => Crypt::encryptString($radiusPassword),
]);

// Create/update client in WinguFi Core
$client = NetworkClient::updateOrCreate(
    [
        'external_id' => $user->id,
        'source_system' => 'company_a_laravel',
    ],
    [
        'tenant_id' => $tenant->id,
        'username' => $user->phone,
        'display_name' => $user->name,
        'phone' => $user->phone,
        'password_hash' => bcrypt($radiusPassword), // hash on the Core side
        'status' => 'active',
        // ... other fields
    ]
);

// Create authorization in WinguFi Core
$authorization = NetworkAuthorization::create([
    'tenant_id' => $tenant->id,
    'client_id' => $client->id,
    'package_id' => $package->id,
    'source_type' => 'payment',
    'source_id' => $payment->id,
    'username' => $user->phone,
    'status' => 'active',
    'starts_at' => now(),
    'expires_at' => now()->addSeconds($package->validity_seconds),
    // ... other fields
]);
```

The company Laravel app sends the password in the `/clients` payload but keeps only the encrypted copy itself.

## External References

Use these fields to link WinguFi Core records back to Laravel records:

- `external_id`: The ID from the Laravel system (e.g., payment ID, user ID)
- `external_type`: The type of record (e.g., 'payment', 'user', 'voucher')
- `source_system`: Identifier for the Laravel instance (e.g., 'company_a_laravel')

## Security Considerations

1. **Never return RADIUS passwords** in WinguFi Core API responses.
2. **Hash the RADIUS password with bcrypt** as soon as it is received in the `/clients` endpoint and store it only as `network_clients.password_hash`.
3. **Use HTTPS** for all API communications, including the captive-portal handoff form action.
4. **Rotate credentials** regularly; support revocation signals from Laravel.
5. **Validate tenant ownership** on all operations.
6. **Log all API calls** for audit purposes, but redact the `password` field before logging.
7. **Validate the handoff request**: signed URL, short expiry (5 minutes), and matching client IP.

## API Endpoints

Base URL: `https://<wingufi-core>/api/v1`

### Health

```http
GET /api/v1/health
```

Response:

```json
{
    "success": true,
    "data": {
        "status": "ok"
    }
}
```

### Synchronize Router

```http
POST /api/v1/routers
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
    "external_id": "router-abc123",
    "name": "Main Hotspot Router",
    "identifier": "abc123",
    "nasname": "203.0.113.10",
    "type": "mikrotik",
    "status": "active"
}
```

### Synchronize Client

```http
POST /api/v1/clients
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
    "external_id": "customer-12345",
    "username": "customer123",
    "display_name": "Customer",
    "phone": "+254700000000",
    "password": "aRandom16CharP@ss",
    "status": "active"
}
```

The `password` field is optional but required for RADIUS-based captive-portal handoff. WinguFi Core must hash it with bcrypt and persist it as `network_clients.password_hash`. The plaintext value must never be returned in subsequent API responses.

### Synchronize Package

```http
POST /api/v1/packages
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
    "external_id": "package-10mb-monthly",
    "name": "10 Mbps Monthly",
    "code": "10MB-M",
    "download_speed": 10000000,
    "upload_speed": 10000000,
    "validity_seconds": 2592000,
    "data_limit_bytes": null,
    "status": "active"
}
```

### Synchronize Authorization

```http
POST /api/v1/authorizations
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
    "external_id": "authorization-98765",
    "client_external_id": "customer-12345",
    "package_external_id": "package-10mb-monthly",
    "status": "active",
    "starts_at": "2026-08-18T10:00:00+03:00",
    "expires_at": "2026-09-18T10:00:00+03:00"
}
```

`client_external_id` must match the client whose `/clients` payload included the RADIUS password. WinguFi Core uses that stored, hashed password when FreeRADIUS requests authorization for the matching username.

### Change Authorization State

```http
PATCH /api/v1/authorizations/{external_id}
Authorization: Bearer <token>
Content-Type: application/json
```

```json
{
    "status": "revoked"
}
```

## Error Responses

Authentication failure:

```json
{
    "success": false,
    "message": "Unauthenticated"
}
```

Validation failure:

```json
{
    "success": false,
    "message": "Validation failed",
    "errors": {
        "external_id": ["The external id field is required."]
    }
}
```

## Example Integration Flow

```php
$client = new \Illuminate\Http\Client\PendingRequest();
$client->withToken('wc_abc123:xxxxxxxx...')
    ->baseUrl('https://wingufi-core.test/api/v1');

// 1. Router
$client->post('/routers', [
    'external_id' => 'router-001',
    'name' => 'Main Router',
    'identifier' => 'router-001',
    'nasname' => '192.168.1.1',
    'type' => 'mikrotik',
    'status' => 'active',
]);

// 2. Client
$client->post('/clients', [
    'external_id' => 'customer-001',
    'username' => 'customer-001',
    'password' => 'aRandom16CharP@ss',
    'status' => 'active',
]);

// 3. Package
$client->post('/packages', [
    'external_id' => 'pkg-1day',
    'name' => '1 Day',
    'code' => '1DAY',
    'download_speed' => 10000000,
    'upload_speed' => 5000000,
    'validity_seconds' => 86400,
    'status' => 'active',
]);

// 4. Authorization
$client->post('/authorizations', [
    'external_id' => 'auth-001',
    'client_external_id' => 'customer-001',
    'package_external_id' => 'pkg-1day',
    'status' => 'active',
    'starts_at' => now()->toIso8601String(),
    'expires_at' => now()->addDay()->toIso8601String(),
]);
```

## Database Connection

WinguFi Core uses a dedicated MySQL database connection named `wingufi_core`. Configure this in your Laravel application's database configuration:

```php
'wingufi_core' => [
    'driver' => 'mysql',
    'host' => env('WINGUFI_DB_HOST', '127.0.0.1'),
    'port' => env('WINGUFI_DB_PORT', '3306'),
    'database' => env('WINGUFI_DB_DATABASE', 'wingufi_core'),
    'username' => env('WINGUFI_DB_USERNAME', 'forge'),
    'password' => env('WINGUFI_DB_PASSWORD', ''),
    'charset' => 'utf8mb4',
    'collation' => 'utf8mb4_unicode_ci',
    'engine' => env('WINGUFI_DB_ENGINE', 'InnoDB'),
],
```

### InnoDB requirement (production)

**WinguFi Core requires InnoDB in production and staging.** The schema relies on foreign key
constraints (`foreignId()->constrained()`) with cascading deletes for referential integrity
across tenants, NAS devices, clients, packages, and authorizations. MyISAM does not enforce
foreign keys and must never be used outside of local development.

`WINGUFI_DB_ENGINE` defaults to `InnoDB`. It should only ever be overridden in a local
development `.env`/`.env.testing` file to work around a broken local MySQL install (e.g. an
InnoDB dictionary corruption bug on a specific WAMP/MySQL 8.4.7 installation) — never in
production, staging, or CI configuration.

## Tenant Isolation

All queries in WinguFi Core must include tenant filtering to ensure strict multi-tenant isolation:

```php
// Always filter by tenant_id
$authorizations = NetworkAuthorization::where('tenant_id', $tenant->id)->get();

// Use model scopes for automatic filtering
class NetworkAuthorization extends Model
{
    protected static function booted()
    {
        static::addGlobalScope('tenant', function ($query) {
            if (auth()->check()) {
                $query->where('tenant_id', auth()->user()->tenant_id);
            }
        });
    }
}
```

## Data Flow

### Purchase Flow

1. User purchases package in Laravel billing app.
2. Laravel app generates and encrypts RADIUS credentials locally.
3. Laravel app creates/updates `network_client` in WinguFi Core, sending the RADIUS password.
4. Laravel app creates `network_authorization` in WinguFi Core.
5. Laravel app redirects the user's browser to a signed `/portal/handoff/{session}` URL.
6. Browser auto-submits RADIUS credentials to the MikroTik `link_login` URL.
7. MikroTik authenticates against FreeRADIUS, which queries WinguFi Core.
8. User is granted network access.

### Session Flow

1. User connects to MikroTik hotspot and is redirected to the captive portal.
2. After authorization, the captive portal hands off RADIUS credentials to MikroTik.
3. MikroTik sends authentication request to FreeRADIUS.
4. FreeRADIUS queries WinguFi Core for the client and authorization.
5. WinguFi Core validates the (hashed) password and authorization state.
6. FreeRADIUS grants access.
7. Session data is recorded in `radius_sessions`.
8. Accounting data is recorded in `radius_accounting`

## Migration Notes

- All migrations use the `wingufi_core` database connection
- Foreign keys are defined within the same database using normal Laravel `foreignId()->constrained()`
- No cross-database foreign keys (use external references instead)
- Soft deletes are used on core entities (tenants, NAS, clients, packages)
- Indexes are optimized for common query patterns
- Migrations assume InnoDB (required for foreign key enforcement); production/staging/CI must run on InnoDB
